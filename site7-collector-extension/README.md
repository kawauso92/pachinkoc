# Site7 Collector Prototype

Version 0.5.2では、Site7の横スライド内に前後台のDOMが残る構造へ対応しました。現在URLの `dn` と一致し、画面内に表示されているオレンジ帯または台番号セレクトを現在台として採用します。確定した現在台のスライド範囲内だけから機種・summary・history・graphを取得します。

ページ読込時に主キーを `currentContext` として固定します。同じURL内でスクロールやDOM表示が変化しても、店舗・機種・台番・営業日・画面種別は再判定しません。状態バーの `CONTEXT LOCKED` が固定中の目印です。

部分summaryをマージする際、未取得のnull項目で既存値を消しません。`normalStarts / payoutTotal / diffBallsFinal` が揃うと使用玉と回転率を再計算し、回転率は小数2桁で保存します。

part取得は画面種別に限定し、D2600は大きいgraphだけ、D2700は履歴本体だけ、D4000/運日データはsummaryだけを保存します。他partは更新せず既存値を保持します。履歴の払出合計は数値noの大当たり行のみを対象とし、対象行・除外行・合計をデバッグ情報に残します。

URLの `dn / pmc / mdc / dtdd` と `D2600 / D2700 / D4000` も解析します。前後台リンクや閲覧履歴内の番号は採用しません。

機種名は `FREE` ラベル付近の青文字リンクを最優先にし、「閲覧履歴」「出玉推移」「大当り履歴」「出玉詳細」「運日データ」などの画面ラベルを拒否します。日付タブが取得できないときは `dtdd=0` を当日、`dtdd=1` を1日前として補助利用します。

閲覧中のサイトセブン（`site777.jp`）ページから、表示済みの台データだけを読み取り、Chrome内に保存する Manifest V3 拡張です。自動巡回、HTTP直取得、ログイン回避、WAF回避は行いません。

## 読み込み手順

1. Chromeで `chrome://extensions/` を開きます。
2. 右上の「デベロッパー モード」をONにします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. この `site7-collector-extension` フォルダを選択します。
5. すでに開いていたサイトセブンのページを再読み込みします。

## 使い方

1. サイトセブンで対象の店舗・機種・台・日付のページを通常どおり開きます。
2. 右下の状態バーで検出台番号、機種、営業日、画面種別を確認します。
3. 拡張アイコンを開き、誤検出や未検出があれば店舗名・機種名・台番号・対象日を補正します。グラフ差玉を目視確認できる場合は「差玉補正」も指定できます。
4. 「現在のページを保存」を押します。別画面へ移動して同じ台・同じ営業日を保存すると、`summary / history / graph` が同じレコードへ追加マージされます。
5. popupの進捗一覧を確認し、「今回データ」「全データ」「デバッグ」のCSVを用途別に書き出します。

自動保存をONにすると、URL・台・日付・画面種別の組み合わせが変わったときに一度だけ保存します。最初はOFFで動作確認することを推奨します。

## 自動巡回（β）

対象機種・日付のSite7ページ（例: 出玉推移 `D2600.do`）を開いた状態でpopupの「自動巡回」から開始すると、現在タブのURLを雛形に `dn`（台番号）と画面ファイル（`D2600/D2700/D4000.do`）だけを差し替えながら、`chrome.tabs.update` で実ブラウザを順に遷移させて各台を取得・保存します。ホストやパスはハードコードせず、開いているページのURLから引き継ぎます。

`background.js` の巡回コントローラが `dn × 画面` のキューを作り、各ステップで「遷移 → 読込完了待ち → `CAPTURE_PAGE` で取得 → ランダム遅延」を繰り返します。遅延（min/max）と取得画面（出玉推移/大当り履歴/出玉詳細）は指定でき、停止ボタンで現ステップ完了後に止まります。`dn` は `181-220` のレンジや `181,182,190-195` のリストで指定します。「ドライラン」を選ぶと巡回せず生成予定URLだけを確認できます。

巡回はあなたの有料セッションのまま実ブラウザを人間的なペースで操作する方式で、HTTP直抜き・anti-bot/WAF回避は行いません。巡回中は対象タブを前面のままにしてください（出玉推移グラフは表示中タブの撮影が必要なため）。巡回時は手動補正（台番号・差玉など）を外し、各台を自動検出します。

Site7はPCアクセスを弾くため、`declarativeNetRequest`（`rules.json`）で `site777.jp` 宛リクエストの `User-Agent` をiPadに固定します。拡張が有効な間はSite7を常にiPadとして開くので、別のUA偽装手段は不要です。`dn` 一覧は当面手入力で、機種台一覧ページからの自動列挙は今後対応します。

## 保存とマージ

通常レコードのキーは次の5項目です。

```text
source + storeName + machineName + daiNormalized + businessDate
```

店舗、機種、台番号、営業日のどれかが不明なデータは、自動マージせず `pending` に保存します。単台ページでは台番号を表示用・比較用ともに `181` の形で保持し、セレクトボックスの元表示が `0181` だった場合は検出候補の `rawValue` に残します。大当り履歴(D2700)はその日の完全な一覧なので、マージ時は過去取得とunionせず最新取得の行で置き換え、`no` をキーに重複排除します（瞬間的に別スライドを拾った古い行が累積して払出合計が水増しされるのを防ぎます）。払出合計はマージ後の行から必ず再計算し、保存値が保存行と一致するようにします。

同一pending候補を再保存した場合は新しい行を増やさず更新します。既存pendingの重複もpopupで読み込んだ時点で圧縮します。更新時は `updatedAt` と `previousValue` を残します。

保存先は `chrome.storage.local` です。JSONは保存構造を維持して出力します。通常CSVはスプレッドシート向けの日本語18列、デバッグCSVは検証向けの詳細列です。通常CSVの `最終差玉` と `推定使用玉` は整数表示に丸めますが、内部値とデバッグCSVの `diffBallsRaw` は小数を保持します。

取得partは画面ごとに固定しています。`D2600.do` は大きい出玉推移グラフだけ、`D2700.do` は履歴テーブルだけ、`D4000.do`／出玉詳細／運日データはsummaryだけを更新します。同一主キーの他partは保持し、機種名未取得でpendingになったpartも後で正しい機種名が得られた時点で統合します。

`D2600.do` の出玉推移ページは自動保存対象です。popupの自動保存設定がOFFでも、ページ表示時に最大面積の出玉推移グラフを選択して保存します。描画が間に合わない場合は最大4回まで再試行します。同じ主キー・同じ取得内容は `unchanged` として再書き込みしません。差玉値など内容が変化した場合だけ既存レコードを更新します。

グラフ軸は薄い水平罫線も検出します。Site7単台グラフの軸は `+30,000 / -30,000` として終点を補間します。終点は「最も右に折れ線色の画素がある列」を採用し、左隣の列に支持される右端だけを終点とするため、序盤の0付近を長く横ばいする部分や凡例・ボタン・注記を終点と誤認しません。線色は水色決め打ちではなく、クロップ内で最も多い有彩色を折れ線色として自動推定するので、ピンクや他色の台でも追従します。

軸スケールは、軸ラベル文字が取得できない場合でも等間隔の水平罫線（10,000玉刻み）から復元します。0線は罫線群の中心に最も近い罫線とし、罫線が3本未満または間隔が不規則な場合だけグラフ領域の8%〜92%を使用して、検証用CSVに警告を残します。

自動保存で `captureVisibleTab` を利用できずDOM canvas解析へ切り替わった場合も、DOM軸ラベル→罫線間隔→8%〜92%の順で軸を決めます。横スライド内に同じグラフDOMが複数あるため、現在台のグラフ選択は**ビューポート中央に最も近いスライド（＝現在表示中の台）**を優先します。面積最大ではなく中央近接で選ぶので、線を持たないグリッド枠コンテナや画面外スライドを誤選択しません。スクショのクロップに折れ線が写っていない（透明レイヤー等）場合は、選択要素のビットマップを直接読むDOMラスタライズへ自動フォールバックします。`graphEndpointMethod` と検出画素数、採用した軸種別・取得方法はデバッグ情報へ残します。

店舗名・画面名・タブ名は機種名として保存しません。既存レコードに正しい機種名がある場合はそれを保持します。graph取得済みでも差玉解析に失敗した場合は、通常CSVの取得状態に `diff:missing`、メモに実際の `diffBallsStatus` を出します。

popupを最初に開いた時刻をブラウザセッションの開始時刻として `chrome.storage.session` に保持します。「今回データ」はその時刻以降に保存・更新された行だけを対象にします。全削除後は削除時刻を新しいセッション境界に更新します。

「今回データをCSV出力」が開始された時点でセッション境界を更新し、出力済みレコードは削除せず過去データ扱いにします。次回の今回CSVには、その後に新規保存・更新されたレコードだけが入ります。「全データCSV出力」では境界を変更しません。

削除処理はスコープを受け取る `deleteCapturedData(criteria)` に集約しています。現在のUIは `all` のみですが、対象日・店舗・台・選択レコード単位の条件を追加できる構造です。

## 現在取得を試みる項目

- 共通: 店舗名、機種名、台番号、営業日、日付信頼度、画面種別、取得URL・時刻
- summary: 大当り、初当り、累計/通常/チャンス中スタート、最高出玉、最終スタート、確率、更新時刻
- history: 回数、時刻、スタート、獲得数、通常/チャンス中判定
- graph: 画像参照、上下軸値・座標、終点座標、1pxあたり差玉、丸めていない推定差玉

グラフ解析時は候補数・候補矩形・選択矩形・軸文字候補・線色候補・画像寸法・水平線・失敗理由も保存します。「デバッグ情報」には直近保存payloadと、読み取り可能なグラフDataURLが含まれます。

単台グラフは `chrome.tabs.captureVisibleTab` で表示中タブを撮影し、DOM矩形に合わせてcropして解析します。Site7は罫線背景と折れ線が別DOMレイヤーの場合があるため、ページの合成表示を自動撮影できるよう `<all_urls>` 権限を使用します。現在はSite7標準の上限 `+30,000`、下限 `-30,000` を仮定し、`axisAssumption` と `axisConfidence` を保存します。グラフ全体が画面内に見えている状態で保存してください。

差玉取得後、summary/historyも揃うと以下を自動計算します。

```text
estimatedUsedBalls = payoutTotal - diffBallsFinal
rotationRate = normalStarts / estimatedUsedBalls * 250
```

期待時給と仕事量は appa の式を使います。機種スペックまたは交換率を解決できない場合は空欄のまま `calculationStatus` と通常CSVのメモへ理由を出します。

機種・店舗マスターは appa/appb と同じGAS `action=masters` から取得し、`chrome.storage.local` に6時間キャッシュします。Site7名とappa名は正規化して照合し、`はじまりの記憶` は `エヴァ17`、`HYPER ARROW美原店` は `美原` として解決します。appaの初期値に合わせ持玉比率100%で期待時給を計算します。

Site7には現金投資・持玉投資・ラウンド内訳がないため、仕事量は `expectedHourlyRaw × normalStarts / jikan` の理論仕事量を出し、`workValueTheoreticalAllHolding` を計算状態に残します。投資・ラウンド内訳が将来渡された場合はappaの実績補正式を優先します。

## グラフ解析の制限

canvasまたはブラウザから画素を読める同一生成元画像に限り、色のあるグラフ線の右端と、画面上の上下軸ラベルを使って差玉を補間します。画像が別生成元でcanvasが汚染される場合、軸ラベルがDOMにない場合、線色を検出できない場合は値を推測せず、以下の状態を保存します。

- `axis_not_detected`
- `graph_not_detected`
- `over_axis_limit`
- `under_axis_limit`

サイト側DOMの実例に合わせたセレクタ調整や、画像OCRは今後の改善対象です。

## 初期確認チェック

- 店舗名、機種名、台番号、選択日が正しいか
- summary/history/graphのうち現在画面にある部分だけが `captured` か
- 同一台・同一日を別画面から保存したときに1行へマージされるか
- 日付不明時に `pending` へ入るか
- JSON/CSVがUTF-8（BOM付き）で開けるか

取得できなかったときはpopupの「デバッグ情報」をコピーすると、URL、検出結果、設定、保存件数を確認できます。
